# Cats of Sands

Браузерная демосцена на Vite и JavaScript. Rust/WASM обновляет мир через `bevy_ecs`, а Canvas 2D отображает его состояние.

## Запуск

Понадобятся Node.js, совместимый с Vite 8 (20.19+ или 22.12+), Rust 1.95+, `wasm-pack` и `make`.

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-pack --locked
npm ci
make dev
```

Открой адрес, указанный Vite. Нажми «Запустить» для базовой сцены или включи «Пустынный спутник», чтобы ускорить первый объект и добавить второй. Клик по спутнику меняет его цвет. Изменения галочек сохраняются в браузере и применяются при следующем нажатии «Запустить».

## Сборка и проверка

```sh
cargo test --locked
npm run build
npm run preview
```

Если установлен `cargo-outdated`, проверку версий зависимостей можно запустить из корня командой `cargo outdated`.

`dev` и `build` собирают WASM перед запуском Vite. После изменения Rust-кода перезапусти dev-сервер или выполни `npm run wasm`.

Устройство симуляции и добавление компонентов, систем и наблюдателей описаны в [документации core](core/README.md).

## Конфигурация

Параметры типов юнитов находятся в [units.yaml](public/config/units.yaml), а стартовая расстановка — в [base.yaml](public/config/base.yaml). Чтобы добавить аддон, положите YAML в [public/config/addons](public/config/addons) и вручную добавьте запись в [addons.json](public/config/addons.json). Укажите уникальный строковый `id`, отображаемое `name` и путь `path` относительно корня сайта, например `config/addons/desert-companion.yaml`. Если хостинг позволяет обновлять статические файлы отдельно, достаточно опубликовать YAML и обновлённый JSON.

Выбор игрока сохраняется по `id` из каталога, поэтому `name` и `path` можно менять с сохранением выбора. Аддон может объявить в каталоге `"depends": ["another-addon"]`. Все перечисленные зависимости нужно включить в форме запуска. После базы применяется первый по порядку каталога аддон, у которого уже применены все зависимости, и так до конца списка. Отсутствующая зависимость или цикл останавливают запуск с сообщением об ошибке.

Каталог `units` содержит записи с `type` и компонентами. В поставляемых файлах идентификаторы типов записаны заглавными буквами. Имена сопоставляются с учётом регистра.

```yaml
units:
  - type: CAT
    Sprite: { radius: 18, color: "#f9c86d" }
    Speed: 60
```

Каждая запись `placements` создаёт отдельный экземпляр с собственным `SimId`. Несколько записей могут ссылаться на один тип. Координаты задаются для каждого экземпляра.

```yaml
placements:
  - type: CAT
    position: { x: 80, y: 150 }
  - type: CAT
    position: { x: 240, y: 180 }
```

Аддон может дописать записи в `placements` и изменить каталог через `units`. Записи с `id` или `type` создают или обновляют тип. `new` требует свободное имя, `override` требует существующее, `update` пропускает отсутствующее, а `delete` удаляет тип. Поля компонентов объединяются рекурсивно, списки внутри компонентов заменяются целиком. Скорость можно задать как `Speed: 60` или `Speed: { value: 60 }`. Пример обоих разделов есть в [desert-companion.yaml](public/config/addons/desert-companion.yaml).

Ядро по-прежнему принимает отдельные конфигурации в старом формате `entities`. Чтобы подключить старый аддон к новой сцене, перенесите определения в `units`, координаты в `placements` и приведите ссылки на базовые типы к новым именам.
