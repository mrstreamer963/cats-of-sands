# Cats of Sands

Браузерная демосцена на Vite и JavaScript. Rust/WASM обновляет мир через `bevy_ecs`, а Canvas 2D отображает его состояние.

## Запуск

Понадобятся Node.js, совместимый с Vite 8 (20.19+ или 22.12+), Rust 1.95+, `wasm-pack` и `make`.

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-pack --locked
npm ci
make dev
```

Открой адрес, указанный Vite. Выбери карту в списке «Карта» и нажми «Запустить» для базовой сцены или включи «Пустынный спутник», чтобы ускорить первый объект и добавить второй. Клик по спутнику меняет его цвет. Изменения галочек сохраняются в браузере и применяются при следующем нажатии «Запустить».

После запуска на экране остаются карта и юниты. Клик по юниту выделяет его, а Shift + клик добавляет или убирает его из выделения. Клик по песку отправляет выбранных юнитов к точке сбора. Esc открывает паузу; из неё можно продолжить игру, сохранить полный снимок в JSON-файл, загрузить снимок из файла или выйти в главное меню. Перед выходом в главное меню всегда запрашивается подтверждение. Esc из диалога загрузки или подтверждения возвращает к предыдущему экрану.

## Сборка и проверка

```sh
cargo test --locked
npm run build
npm run preview
```

Если установлен `cargo-outdated`, проверку версий зависимостей можно запустить из корня командой `cargo outdated`.

`dev` и `build` собирают WASM перед запуском Vite. После изменения Rust-кода перезапусти dev-сервер или выполни `npm run wasm`.

Устройство симуляции и добавление компонентов, систем и наблюдателей описаны в [документации core](core/README.md).

## Конфигурация

Параметры типов юнитов находятся в [units.yaml](public/data/units.yaml), а стартовая расстановка — в [map1.yaml](public/data/maps/map1.yaml). Базовый [resource.json](public/data/resource.json) перечисляет общие YAML в поле `layers` и доступные карты в поле `maps`. Чтобы добавить карту, положите YAML в `public/data/maps/` и добавьте путь вида `maps/map2.yaml` в `maps`. Первая карта выбрана по умолчанию. При запуске сначала применяются общие слои, затем выбранная карта, затем аддоны. Для нового аддона создайте отдельную папку в [public/addons](public/addons) и добавьте её имя в [addons.json](public/addons/addons.json). Каталог содержит упорядоченный массив имён папок, например `["desert-companion"]`.

Карта [desert.tmj](public/data/maps/desert.tmj) открывается в Tiled. В [desert.yaml](public/data/maps/desert.yaml) поле `tiled` указывает на этот файл, а `ground` и `walls` задают игровые параметры типов. В Tiled используйте одноимённые тайловые слои и указывайте тип каждого тайла строковым свойством `terrain`. В игре колесо меняет масштаб, перетаскивание двигает камеру, а клик по земле отправляет туда выделенных котов.

В папке находятся `resource.json`, игровой YAML и при необходимости ресурсы, например `sprites/companion.png` и `sounds/meow.ogg`. В [манифесте](public/addons/desert-companion/resource.json) укажите уникальный строковый `id`, отображаемое `name` и упорядоченный список `layers` с путями к YAML относительно папки аддона. Пути к ресурсам также задаются относительно этой папки.

Перед публикацией выполните `npm run prepare:addons`, чтобы обновить поле `sha256` в манифестах. Команды `dev` и `build` выполняют этот шаг автоматически. После изменения YAML, метаданных, путей или ресурсов пересчитайте хэш и опубликуйте каталог вместе с подготовленными папками.

Выбор игрока сохраняется по `id` из манифеста, поэтому папку и отображаемое имя можно менять с сохранением выбора. Манифест может объявить `"depends": ["another-addon"]`. Все перечисленные зависимости нужно включить в форме запуска. После базы применяется первый по порядку каталога аддон, у которого уже применены все зависимости, и так до конца списка. Отсутствующая зависимость или цикл останавливают запуск с сообщением об ошибке.

Каталог `units` содержит записи с `type` и компонентами. В поставляемых файлах идентификаторы типов записаны заглавными буквами. Имена сопоставляются с учётом регистра.

```yaml
units:
  - type: CAT
    Sprite: { radius: 18, color: "#f9c86d" }
    Speed: 60
```

Каждая запись `placements` создаёт отдельный экземпляр с собственным `SimId`. Несколько записей могут ссылаться на один тип. Координаты задаются для каждого экземпляра.

```yaml
placements:
  - type: CAT
    position: { x: 80, y: 150 }
  - type: CAT
    position: { x: 240, y: 180 }
```

Аддон может дописать записи в `placements` и изменить каталог через `units`. Записи с `id` или `type` создают или обновляют тип. `new` требует свободное имя, `override` требует существующее, `update` пропускает отсутствующее, а `delete` удаляет тип. Поля компонентов объединяются рекурсивно, списки внутри компонентов заменяются целиком. Скорость можно задать как `Speed: 60` или `Speed: { value: 60 }`. Пример обоих разделов есть в [YAML аддона desert-companion](public/addons/desert-companion/units.yaml).

Ядро по-прежнему принимает отдельные конфигурации в старом формате `entities`. Чтобы подключить старый аддон к новой сцене, перенесите определения в `units`, координаты в `placements` и приведите ссылки на базовые типы к новым именам.
