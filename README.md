# Cats of Sands

Браузерная демосцена на Vite и JavaScript. Rust/WASM обновляет мир через `bevy_ecs`, а Canvas 2D отображает его состояние.

## Запуск

Понадобятся Node.js, совместимый с Vite 8 (20.19+ или 22.12+), Rust 1.95+, `wasm-pack` и `make`.

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-pack --locked
npm ci
make dev
```

Открой адрес, указанный Vite. Нажми «Запустить» для базовой сцены или включи «Пустынный спутник», чтобы ускорить первый объект и добавить второй. Клик по спутнику меняет его цвет. Изменения галочек сохраняются в браузере и применяются при следующем нажатии «Запустить».

## Сборка и проверка

```sh
cargo test --locked
npm run build
npm run preview
```

Если установлен `cargo-outdated`, проверку версий зависимостей можно запустить из корня командой `cargo outdated`.

`dev` и `build` собирают WASM перед запуском Vite. После изменения Rust-кода перезапусти dev-сервер или выполни `npm run wasm`.

Устройство симуляции и добавление компонентов, систем и наблюдателей описаны в [документации core](core/README.md).

## Конфигурация

Базовая сцена находится в [base.yaml](public/config/base.yaml). Чтобы добавить аддон, положите YAML в [public/config/addons](public/config/addons) и вручную добавьте запись в [addons.json](public/config/addons.json). Укажите уникальный строковый `id`, отображаемое `name` и путь `path` относительно корня сайта, например `config/addons/desert-companion.yaml`. Если хостинг позволяет обновлять статические файлы отдельно, достаточно опубликовать YAML и обновлённый JSON.

Выбор игрока сохраняется по `id` из каталога, поэтому `name` и `path` можно менять с сохранением выбора. Выбранные аддоны применяются в порядке записей в JSON. Ключи в `entities` — стабильные ID. Отображения объединяются рекурсивно, списки заменяются целиком, а значение более позднего слоя имеет приоритет.

В словаре `components` можно задать `Sprite` с полями `position`, `radius` и `color`, `Speed` с полем `value` и `ClickColor` с полем `color`. Поля каждого компонента объединяются по тем же правилам. Прежние поля сущности по-прежнему поддерживаются. Если заданы оба формата, явно указанный компонент `Sprite` или `Speed` целиком заменяет соответствующие поля прежнего формата. Рабочий пример есть в [desert-companion.yaml](public/config/addons/desert-companion.yaml).

`entities` также принимает список записей. `id` и `type` создают или обновляют сущность. `new` требует свободный ID, `override` требует существующий, `update` пропускает отсутствующий, а `delete` удаляет сущность по ID. Записи применяются по порядку. В списке `components` записи сопоставляются по `type`, поэтому можно изменить одно поле компонента.

```yaml
entities:
  - override: companion
    components:
      - type: Sprite
        color: "#ffcc00"
```
