# Cats of Sands

Браузерная демосцена на Vite и JavaScript. Rust/WASM обновляет мир через `bevy_ecs`, а Canvas 2D отображает его состояние.

## Запуск

Понадобятся Node.js, совместимый с Vite 8 (20.19+ или 22.12+), Rust 1.95+, `wasm-pack` и `make`.

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-pack --locked
npm ci
make dev
```

Открой адрес, указанный Vite. Нажми «Запустить» для базовой сцены или включи «Пустынный спутник», чтобы ускорить первый объект и добавить второй. Клик по спутнику меняет его цвет. Изменения галочек сохраняются в браузере и применяются при следующем нажатии «Запустить».

## Сборка и проверка

```sh
cargo test --locked
npm run build
npm run preview
```

Если установлен `cargo-outdated`, проверку версий зависимостей можно запустить из корня командой `cargo outdated`.

`dev` и `build` собирают WASM перед запуском Vite. После изменения Rust-кода перезапусти dev-сервер или выполни `npm run wasm`.

Устройство симуляции и добавление компонентов, систем и наблюдателей описаны в [документации core](core/README.md).

## Конфигурация

Базовая сцена находится в [base.yaml](public/config/base.yaml). Чтобы добавить аддон, положите YAML в [public/config/addons](public/config/addons) и вручную добавьте запись в [addons.json](public/config/addons.json). Укажите уникальный строковый `id`, отображаемое `name` и путь `path` относительно корня сайта, например `config/addons/desert-companion.yaml`. Если хостинг позволяет обновлять статические файлы отдельно, достаточно опубликовать YAML и обновлённый JSON.

Выбор игрока сохраняется по `id` из каталога, поэтому `name` и `path` можно менять с сохранением выбора. Аддон может объявить в каталоге `"depends": ["another-addon"]`. Все перечисленные зависимости нужно включить в форме запуска. После базы применяется первый по порядку каталога аддон, у которого уже применены все зависимости, и так до конца списка. Отсутствующая зависимость или цикл останавливают запуск с сообщением об ошибке. Ключи в `entities` — строковые имена типов. При запуске симуляция создаёт один экземпляр каждого типа и присваивает ему числовой `SimId`. Отображения объединяются рекурсивно, списки заменяются целиком, а значение более позднего слоя имеет приоритет.

Компоненты задаются ключами прямо под именем типа. `Position` содержит `x` и `y`, `Sprite` — `radius` и `color`, `Speed` — `value`, `ClickColor` — `color`. Поля компонента объединяются рекурсивно. Для типа без компонентов используйте `cat: {}`. Если в старом YAML есть обёртка `components`, перенесите её содержимое в описание типа. Прежний список внутри `components` преобразуйте в ключи по именам из `type`. Рабочий пример есть в [desert-companion.yaml](public/config/addons/desert-companion.yaml).

`entities` также принимает список записей. `id` и `type` создают или обновляют описание типа. `new` требует свободное имя типа, `override` требует существующее, `update` пропускает отсутствующее, а `delete` удаляет описание по имени. Записи применяются по порядку. Ключи рядом с операцией — имена компонентов. Можно изменить одно поле компонента, сохранив остальные.

```yaml
entities:
  - override: companion
    Sprite: { color: "#ffcc00" }
```
