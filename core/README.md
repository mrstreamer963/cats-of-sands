# sand-simulation

`core` — ядро симуляции Cats of Sands на Rust и Bevy ECS. Оно загружает конфигурацию, владеет игровым миром и предоставляет браузеру API через WASM. JavaScript отвечает за ввод и отрисовку Canvas.

## Как работает симуляция

1. `Session::new` передаёт упорядоченные слои YAML в `Simulation::from_layers`. Модуль `config` объединяет описания по имени типа, а компоненты по типу, и проверяет итоговые данные до создания мира.
2. `Session::advance` получает прошедшее время в секундах и вызывает `Simulation::step` для накопившихся шагов по 1/60 секунды. Тик начинается с команд, затем система `move_entities` обновляет положение объектов с `Position` и `Speed`.
3. `Session::snapshot` возвращает снимок всех сущностей. `Session::click` ставит клик в очередь на ближайший тик. При исполнении команды наблюдатель `apply_click_color` обрабатывает событие `Clicked` и меняет цвет цели с компонентами `Sprite` и `ClickColor`. Факт изменения цвета доступен через `drain_events` вместе с тиком и числовым `SimId` цели.

Для прогона из Rust создайте `Simulation` из YAML-слоёв, передайте `Command::Click` и номер тика в `submit_command`, затем вызовите `step(n)`. `current_tick()` возвращает номер ближайшего тика, начиная с нуля. Команды одного тика исполняются в порядке добавления, команды для прошедших тиков отклоняются. В WASM для пошагового прогона доступны `step(n)` и `submit_click(tick, id)`. Номера тиков в API JavaScript представлены типом `BigInt`.

Каждый `EntitySnapshot` содержит числовое поле `id` экземпляра и строковое поле `type` из YAML. Снимок экспортирует `Position` как `position` с полями `x` и `y`, а `Sprite` как `sprite` с полями `radius` и `color`. Canvas рисует и выбирает по клику сущности, у которых есть оба компонента. При запуске экземпляры создаются в порядке записей `placements`. Координаты из записи задают `Position` экземпляра. `spawn(type_name)` создаёт ещё один экземпляр, `despawn(id)` удаляет его. Удалённый ID больше не выдаётся в этой сессии, поэтому ожидающая команда для него пропускается. В JavaScript ID экземпляров имеют тип `Number`.

Координаты, радиусы и скорости хранятся в `Fixed` (Q32.32). YAML-значения округляются до ближайшего представимого числа, а перемещение за тик вычисляется целочисленным делением скорости на 60 с округлением к нулю. Для Canvas координаты и радиус преобразуются в `Number` при формировании снимка.

Формат YAML и пример аддона описаны в разделе «Конфигурация» корневого README.

## Как расширять ядро

- **Компонент.** Добавьте файл в `src/components/`. Объявите тип Bevy и загрузчик, который десериализует и проверяет поля, затем возвращает операцию вставки через `prepare`. Подключите модуль и зарегистрируйте имя типа в `src/components.rs`. Простой пример — `Speed`.
- **Система.** Добавьте файл в `src/systems/`, подключите его в `src/systems.rs` и зарегистрируйте функцию в расписании в `Simulation::from_config`.
- **Наблюдатель.** Добавьте файл в `src/observers/`, подключите его в `src/observers.rs` и зарегистрируйте функцию через `world.add_observer` в `Simulation::from_config`. Для реакции на конкретную сущность используйте `EntityEvent`, как в примере `Clicked`.

```sh
cargo test --locked -p sand-simulation

```
