# browser-game-runtime Specification

## Purpose

Позволяет запустить демонстрационную игровую сцену в браузере и увидеть результат обновления игрового мира.
## Requirements
### Requirement: Запуск демонстрационной сцены

Браузерное приложение SHALL запускать новую симуляцию с итоговой конфигурацией после нажатия «Запустить» и отображать её состояние на Canvas 2D.

#### Scenario: Запуск с базовой конфигурацией

- **WHEN** игрок запускает игру без аддонов
- **THEN** на холсте отображается один движущийся объект из базовой конфигурации

#### Scenario: Запуск с демонстрационным аддоном

- **WHEN** игрок запускает игру с демонстрационным аддоном
- **THEN** скорость базового объекта отличается от базовой, и на холсте отображается второй объект

#### Scenario: Повторный запуск

- **WHEN** игрок меняет выбор аддонов и запускает игру повторно
- **THEN** начинается новая симуляция из начального состояния с новым набором аддонов

### Requirement: Реакция сущности на клик

Попадание SHALL определяться по положению объекта в последнем отрисованном кадре. Обычный клик по видимому объекту SHALL поставить команду для его `SimId` на ближайший тик. При исполнении команда SHALL менять цвет цели на цвет компонента `ClickColor`, если он присутствует. При перекрытии SHALL выбираться объект, нарисованный последним. Клик вне объектов и Shift + клик SHALL пропускать реакцию сущности.

#### Scenario: Клик по спутнику

- **WHEN** игрок включает аддон «Пустынный спутник» и кликает по спутнику
- **THEN** только спутник меняет цвет и продолжает движение

#### Scenario: Клик по объекту без реакции

- **WHEN** игрок кликает по объекту без `ClickColor`
- **THEN** цвет объектов сохраняется

#### Scenario: Клик по промежуточной позиции

- **WHEN** игрок кликает по видимому кругу движущегося спутника в кадре с интерполяцией
- **THEN** команда клика адресуется спутнику по его `SimId`

### Requirement: Отрисовка между тиками

Браузер SHALL преобразовывать время кадров в шаги по 1/60 секунды и отрисовывать сцену после выполнения доступных шагов. Canvas SHALL рисовать и выбирать по клику только записи с полями `position` и `sprite`.

#### Scenario: Разная частота отрисовки

- **WHEN** две симуляции стартуют из одного состояния и выполняют одинаковое число шагов при разной частоте кадров
- **THEN** снимки содержат одинаковые позиции объектов

#### Scenario: Кадр между тиками

- **WHEN** в двух последних завершённых тиках объект занимал разные позиции без перехода через край сцены
- **THEN** браузер линейно интерполирует позицию для отрисовки по доле времени, накопленной для следующего тика
- **AND** игровая позиция в снимке соответствует последнему завершённому тику

#### Scenario: Первый кадр

- **WHEN** браузер рисует сцену до первого тика
- **THEN** объект отображается в начальной позиции

#### Scenario: Переход через край сцены

- **WHEN** движущийся объект переносится через край сцены и разница горизонтальных координат превышает половину её ширины
- **THEN** браузер отображает текущую горизонтальную позицию сразу, без прохода через середину сцены

#### Scenario: Запись без позиции или спрайта

- **WHEN** в снимке есть запись без `position` или без `sprite`
- **THEN** Canvas её не рисует и не выбирает по клику

### Requirement: Выделение и отправка приказа движения

Обычный клик по юниту SHALL выделять только его. Shift + клик по юниту SHALL менять его присутствие в выделении. Проверка попадания SHALL использовать положение юнита в последнем отрисованном кадре. Выделенные юниты SHALL иметь видимый контур. При повторном запуске сцены выделение SHALL сбрасываться.

#### Scenario: Изменение выделения

- **WHEN** игрок кликает по одному юниту, затем с Shift кликает по второму
- **THEN** оба юнита выделены
- **AND** повторный Shift + клик по второму снимает выделение только с него

#### Scenario: Общий приказ

- **WHEN** игрок с несколькими выделенными юнитами кликает по пустому месту
- **THEN** браузер ставит один приказ на ближайший тик

#### Scenario: Клик по земле без выделения

- **WHEN** игрок кликает по пустому месту без выделения
- **THEN** приказ перемещения не создаётся

### Requirement: Разделение главного меню и игрового экрана
После успешного запуска приложения SHALL показывать игровой экран только с картой и юнитами, без формы настройки запуска и постоянных панелей. Существующая форма запуска SHALL оставаться главным меню.

#### Scenario: Начало новой игры
- **WHEN** игрок успешно запускает выбранную карту из главного меню
- **THEN** приложение показывает игровое поле с картой и объектами
- **AND** элементы настройки запуска не отображаются поверх игрового поля

#### Scenario: Возврат в главное меню
- **WHEN** игрок подтверждает выход из партии в главное меню
- **THEN** игровое поле скрывается
- **AND** снова отображается форма настройки запуска

### Requirement: Пауза по клавише Esc
Во время партии клавиша Esc SHALL открывать меню паузы и приостанавливать симуляцию. Повторное нажатие Esc в меню паузы SHALL закрывать его и возобновлять симуляцию.

#### Scenario: Открытие паузы
- **WHEN** игрок нажимает Esc во время активной партии
- **THEN** отображается меню паузы
- **AND** время симуляции останавливается до продолжения

#### Scenario: Продолжение партии
- **WHEN** игрок нажимает Esc повторно или выбирает «Продолжить»
- **THEN** меню паузы закрывается
- **AND** симуляция продолжается без скачка игрового времени

#### Scenario: Игровой ввод во время паузы
- **WHEN** меню паузы открыто и игрок нажимает на игровое поле или отдаёт игровую команду
- **THEN** игровая команда не выполняется

### Requirement: Действия меню паузы
Меню паузы SHALL предоставлять действия «Продолжить», «Сохранить игру», «Загрузить игру», «Настройки» и «В главное меню».

#### Scenario: Переход к сохранению
- **WHEN** игрок выбирает «Сохранить игру»
- **THEN** приложение скачивает файл с полным снимком текущей партии

#### Scenario: Переход к загрузке
- **WHEN** игрок выбирает «Загрузить игру»
- **THEN** приложение предлагает выбрать файл сохранения

#### Scenario: Esc из диалога сохранения или загрузки
- **WHEN** игрок нажимает Esc в диалоге сохранения или выбора файла
- **THEN** приложение возвращается в меню паузы, не возобновляя игру

#### Scenario: Возврат в главное меню
- **WHEN** игрок выбирает «В главное меню» и подтверждает выход
- **THEN** приложение закрывает текущую партию и показывает существующую форму запуска

#### Scenario: Открытие настроек
- **WHEN** игрок выбирает «Настройки» в меню паузы
- **THEN** приложение открывает настройки, сохраняя паузу
- **AND** «Назад» и Esc возвращают игрока в меню паузы

### Requirement: Файловый снимок партии
Приложение SHALL экспортировать и импортировать версионированный файл полного снимка партии, достаточный для восстановления конфигурации, состояния мира и игрового представления.

#### Scenario: Экспорт состояния партии
- **WHEN** игрок сохраняет игру на паузе
- **THEN** браузер скачивает файл, содержащий выбранную карту, аддоны и полный текущий снимок игры

#### Scenario: Импорт снимка
- **WHEN** игрок выбирает файл снимка и подтверждает замену текущей партии
- **THEN** приложение восстанавливает конфигурацию, состояние мира, выделение юнитов и позицию камеры
- **AND** загруженная партия открывается на паузе

#### Scenario: Ошибка загрузки снимка
- **WHEN** выбранный файл повреждён или содержит неподдерживаемую версию
- **THEN** приложение показывает понятную ошибку
- **AND** текущая партия остаётся доступной на паузе

### Requirement: Подтверждение выхода и замены партии
Перед каждым выходом в главное меню приложение SHALL запрашивать подтверждение. Перед загрузкой снимка поверх активной партии приложение SHALL также запрашивать подтверждение.

#### Scenario: Замена текущей партии
- **WHEN** игрок загружает файл снимка во время активной партии
- **THEN** приложение просит подтвердить замену текущей партии до её закрытия

#### Scenario: Подтверждение выхода
- **WHEN** игрок выбирает выход в главное меню, в том числе после сохранения
- **THEN** приложение всегда просит подтвердить выход до закрытия партии

### Requirement: Настройка показа маршрутов

Приложение SHALL предоставлять в настройках чекбокс «Показывать планируемый путь юнита к цели». По умолчанию показ SHALL быть выключен. Выбор SHALL сохраняться в браузере независимо от партии и файла сохранения.

#### Scenario: Первое открытие настроек
- **WHEN** игрок открывает настройки без ранее сохранённого выбора
- **THEN** чекбокс выключен

#### Scenario: Сохранение выбора
- **WHEN** игрок включает показ и перезагружает страницу
- **THEN** в следующей партии показ включён
- **AND** загрузка снимка партии сохраняет текущую настройку браузера

### Requirement: Оставшийся маршрут выделенных юнитов

При включённой настройке браузер SHALL рисовать для каждого выделенного юнита с активным маршрутом линию от его видимой позиции через оставшиеся точки пути до назначенной цели. При выключенной настройке линии SHALL быть скрыты.

#### Scenario: Приказ движения в обход препятствия
- **WHEN** выделенный юнит получает приказ идти к цели за препятствием
- **THEN** линия следует по рассчитанному обходу до цели

#### Scenario: Приказ группе
- **WHEN** несколько выделенных юнитов получают групповой приказ
- **THEN** линия каждого юнита с маршрутом ведёт к назначенному ему месту

#### Scenario: Изменение маршрута
- **WHEN** юнит проходит точку или симуляция перестраивает путь
- **THEN** линия показывает актуальные оставшиеся точки

#### Scenario: Скрытие линии
- **WHEN** юнит прибывает, теряет маршрут или перестаёт быть выделенным
- **THEN** его линия исчезает
