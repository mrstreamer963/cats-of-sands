## Purpose

Позволяет менять конфигурацию демонстрационной игры поставляемыми YAML-аддонами и восстанавливать выбор игрока при повторном открытии страницы.

## ADDED Requirements

### Requirement: Выбор и сохранение аддонов

Стартовый экран SHALL показывать галочки для поставляемых аддонов. Приложение SHALL сохранять ID выбранных аддонов в браузерном хранилище и восстанавливать доступные ID после перезагрузки.

#### Scenario: Восстановление выбора

- **WHEN** игрок меняет набор аддонов и перезагружает страницу
- **THEN** стартовый экран показывает сохранённый выбор

#### Scenario: Аддон исчез из каталога

- **WHEN** сохранённый выбор содержит ID, которого больше нет в каталоге
- **THEN** приложение пропускает этот ID и восстанавливает оставшиеся доступные аддоны

### Requirement: Порядок и правила объединения

Приложение SHALL применять выбранные аддоны поверх базового YAML в порядке каталога. Коллекция сущностей SHALL объединяться по стабильному ID. Поля объектов SHALL объединяться рекурсивно, списки SHALL заменяться целиком, а конфликтующие значения SHALL заменяться значением более позднего слоя.

#### Scenario: Частичное переопределение и добавление

- **WHEN** выбранный аддон меняет скорость базовой сущности по ID и объявляет сущность с новым ID
- **THEN** базовая сущность получает новую скорость и сохраняет исходную стартовую позицию
- **AND** итоговая конфигурация содержит обе сущности

#### Scenario: Конфликт двух аддонов

- **WHEN** два выбранных аддона меняют одно поле или один список
- **THEN** итоговое значение поля или всего списка берётся из аддона, который расположен позже в каталоге

#### Scenario: Аддон выключен

- **WHEN** аддон присутствует в каталоге, но его галочка снята
- **THEN** его данные не влияют на итоговую конфигурацию

### Requirement: Ошибки конфигурации

Приложение SHALL проверять итоговую конфигурацию до создания мира. При ошибке оно SHALL сохранить экран запуска доступным и показать имя файла и причину при ошибке загрузки или разбора либо путь к проблемному полю и причину при ошибке итоговой валидации.

#### Scenario: Недоступный или некорректный YAML

- **WHEN** базовый файл или выбранный аддон не загружается либо не разбирается как YAML
- **THEN** новая симуляция не запускается, а стартовый экран показывает имя файла и причину

#### Scenario: Некорректное итоговое значение

- **WHEN** объединённые данные содержат недопустимое значение
- **THEN** новая симуляция не запускается, а стартовый экран показывает проблемное поле и причину
