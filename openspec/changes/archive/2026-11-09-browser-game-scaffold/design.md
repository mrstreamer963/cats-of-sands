## Context

В репозитории ещё нет приложения. Границы первой поставки описаны в [proposal.md](proposal.md). Браузер загружает статические ресурсы Vite и запускает один экземпляр игровой сессии.

## Goals / Non-Goals

**Goals**

- Определить границу между браузерным приложением и ядром симуляции.
- Использовать один путь сборки конфигурации для браузера и нативных Rust-проверок.

**Non-Goals**

- Загрузка пользовательских YAML, смена аддонов внутри работающей сессии, сохранение игрового мира.

## Decisions

### Браузер управляет кадром, Rust управляет миром

Vite и обычный JavaScript управляют экраном выбора, загрузкой ресурсов и Canvas 2D. Rust собирается для `wasm32-unknown-unknown` с привязками `wasm-bindgen`. Оформить генерацию браузерного WASM-пакета как явный шаг перед запуском dev-сервера и production-сборкой.

JS передаёт прошедшее время из `requestAnimationFrame`. Rust накапливает время и исполняет расписание `bevy_ecs` с шагом 1/60 секунды. На кадр принимается не более 250 мс прошедшего времени, чтобы ограничить число шагов после фоновой паузы. JS читает один снимок на кадр. Снимок содержит стабильный ID, координаты и параметры отрисовки. При успешном повторном запуске предыдущий цикл завершается, а его сессия освобождается перед запуском нового цикла.

### Каталог задаёт порядок, хранилище хранит выбор

Каталог в JS задаёт стабильный ID, название и URL каждого поставляемого аддона. JS загружает базовый YAML и только выбранные аддоны, передавая Rust упорядоченный список пар «имя файла, текст». URL статических файлов учитывают базовый путь Vite. JS сохраняет массив выбранных ID в `localStorage` при изменении галочек. При чтении выбор пересекается с каталогом. При отсутствии или повреждении записи по умолчанию активных аддонов нет. При недоступном хранилище текущий выбор остаётся доступен в памяти на время работы страницы.

### Конфигурация собирается до создания мира

Каждый YAML разбирается отдельно, чтобы ошибки содержали имя источника. Корень документа представляет собой отображение, а `entities` — отображение стабильных ID в настройки сущностей. Так сущности следуют общим правилам слияния отображений, а обычные YAML-последовательности заменяются целиком. Слияние идёт от базы к выбранным аддонам в порядке каталога. Затем итоговые данные преобразуются в типизированную конфигурацию и проверяются до создания ECS-мира. Ошибка валидации включает путь к полю и причину. Базовый YAML задаёт один движущийся объект. Демонстрационный аддон изменяет его скорость и добавляет вторую сущность.

## Risks / Trade-offs

- Фоновая пауза браузера может дать большой интервал между кадрами. Ограничение времени на кадр удерживает объём работы при возобновлении.
- Частичный аддон может оставить итоговые данные неполными. Проверка объединённой конфигурации до создания мира позволяет вывести ошибку на экране запуска.
- Устаревший WASM-пакет может расходиться с JS. Dev-запуск и production-сборка используют один шаг генерации пакета.
