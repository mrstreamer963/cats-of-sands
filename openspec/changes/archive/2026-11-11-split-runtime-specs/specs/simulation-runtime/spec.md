## Purpose

Определяет порядок тиков, очередь команд и событий, жизненный цикл экземпляров и формат снимков состояния.

## ADDED Requirements

### Requirement: Фиксированный шаг симуляции

Ядро SHALL позволять выполнить заданное число тиков независимо от кадров браузера. Координаты, радиус и скорость SHALL храниться в знаковом формате Q32.32.

#### Scenario: Пошаговый запуск без браузера

- **WHEN** хост просит ядро выполнить два тика с момента запуска
- **THEN** ядро выполняет тики 0 и 1, а следующим становится тик 2

### Requirement: Команды и события по тикам

Ядро SHALL принимать команды на заданный тик, начиная с тика 0, и отклонять команды для прошедших тиков. Команды одного тика SHALL исполняться в порядке добавления перед движением. Изменение цвета SHALL порождать событие с тиком, ID экземпляра и новым цветом. Чтение событий SHALL забирать накопленные события из очереди.

#### Scenario: Клик на будущем тике

- **WHEN** команда клика поставлена на тик 1 и ядро завершает тик 0
- **THEN** цвет ещё не изменился и события изменения цвета нет
- **AND** после исполнения тика 1 событие возвращается при первом чтении и отсутствует при повторном чтении

#### Scenario: Команда для прошедшего тика

- **WHEN** хост отправляет команду для уже завершённого тика
- **THEN** ядро возвращает ошибку

### Requirement: Идентификаторы и снимки экземпляров

Для старых конфигураций только с `entities` симуляция SHALL создавать один экземпляр каждого итогового YAML-типа в порядке имён. Ядро SHALL позволять создать дополнительный экземпляр по имени типа и удалить экземпляр по числовому `SimId`. Выданный ID SHALL сохраняться до удаления и никогда не выдаваться повторно в этой сессии. Снимок SHALL содержать все живые экземпляры с `id` и `type`. Поле `position` SHALL включаться только при наличии `Position` и содержать `x` и `y`. Поле `sprite` SHALL включаться только при наличии `Sprite` и содержать `radius` и `color`.

#### Scenario: Два экземпляра одного типа

- **WHEN** два экземпляра одного типа присутствуют в снимке и команда адресована одному из них
- **THEN** их ID различаются и меняется только адресованный экземпляр

#### Scenario: Команда для удалённого экземпляра

- **WHEN** экземпляр удаляется до исполнения команды для его ID и создаётся другой экземпляр того же типа
- **THEN** новый экземпляр получает новый ID, а отложенная команда пропускается

#### Scenario: Экземпляр без спрайта

- **WHEN** экземпляр не содержит `Sprite`
- **THEN** он присутствует в снимке без поля `sprite`

#### Scenario: Экземпляр без позиции

- **WHEN** экземпляр содержит `Sprite`, но не содержит `Position`
- **THEN** он присутствует в снимке с полем `sprite`, без поля `position`,

### Requirement: Создание экземпляров по расстановке

При запуске с каталогом типов симуляция SHALL создать экземпляры в порядке записей расстановки и выдать каждой отдельный `SimId`. Для конфигурации только с `entities` SHALL сохраниться запуск с одним экземпляром каждого типа.

#### Scenario: Каталог содержит неиспользуемый тип

- **WHEN** тип есть в каталоге, но отсутствует в расстановке
- **THEN** он доступен для последующего создания экземпляров и отсутствует в стартовом мире
