## ADDED Requirements

### Requirement: Создание экземпляров по расстановке

При запуске с каталогом типов симуляция SHALL создать экземпляры в порядке записей расстановки и выдать каждой отдельный `SimId`. Для конфигурации только с `entities` SHALL сохраниться запуск с одним экземпляром каждого типа.

#### Scenario: Каталог содержит неиспользуемый тип

- **WHEN** тип есть в каталоге, но отсутствует в расстановке
- **THEN** он доступен для последующего создания экземпляров и отсутствует в стартовом мире

## MODIFIED Requirements

### Requirement: 

Для старых конфигураций только с `entities` симуляция SHALL создавать один экземпляр каждого итогового YAML-типа в порядке имён. Ядро SHALL позволять создать дополнительный экземпляр по имени типа и удалить экземпляр по числовому `SimId`. Выданный ID SHALL сохраняться до удаления и никогда не выдаваться повторно в этой сессии. Снимок SHALL содержать все живые экземпляры с `id` и `type`. Поле `position` SHALL включаться только при наличии `Position` и содержать `x` и `y`. Поле `sprite` SHALL включаться только при наличии `Sprite` и содержать `radius` и `color`. Canvas SHALL рисовать и выбирать по клику только записи с обоими полями.

#### Scenario: Два экземпляра одного типа

- **WHEN** два экземпляра одного типа присутствуют в снимке и команда адресована одному из них
- **THEN** их ID различаются и меняется только адресованный экземпляр

#### Scenario: Команда для удалённого экземпляра

- **WHEN** экземпляр удаляется до исполнения команды для его ID и создаётся другой экземпляр того же типа
- **THEN** новый экземпляр получает новый ID, а отложенная команда пропускается

#### Scenario: Экземпляр без спрайта

- **WHEN** экземпляр не содержит `Sprite`
- **THEN** он присутствует в снимке без поля `sprite` и не рисуется на Canvas

#### Scenario: Экземпляр без позиции

- **WHEN** экземпляр содержит `Sprite`, но не содержит `Position`
- **THEN** он присутствует в снимке с полем `sprite`, без поля `position`, и не рисуется на Canvas
